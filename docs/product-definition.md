# Project Alice - Product Definition

## Overview

Aliceは、ユーザー専用のパーソナルAIアシスタントです。

単なる質問回答AIや開発支援AIではなく、
仕事・生活・情報・デバイスを横断してユーザーを支援する存在を目指します。

Aliceは、ユーザーの好み、価値観、経験、過去の判断、利用履歴などを継続的に蓄積・活用し、
一般的な回答ではなく「ユーザーにとって最適な回答・提案・行動」を提供します。

---

## Purpose

Aliceの目的は、
ユーザーの日常に存在する判断・情報収集・作業・操作を支援し、
ユーザーが本来集中したいことに時間を使える環境を作ることです。

Aliceを「使う」のではなく、
Aliceと一緒に仕事や生活を行う環境を作ることを目指します。

---

## Support Areas

Aliceは主に以下の領域を支援します。

### 1. 技術支援

ソフトウェア開発における技術パートナーとして支援します。

例:

- 技術相談
- 技術選定
- システム設計
- アーキテクチャ検討
- コードレビュー
- 要件・設計レビュー
- 学習支援
- 開発プロジェクト支援

技術領域では、
テックリードやCTOに近い視点から支援することを目指します。

ただし、Aliceは開発支援専用AIではありません。

技術支援はAliceが持つ能力の一つとして扱います。

---

### 2. 生活支援

ユーザーの状況や好みを考慮し、
日常生活における意思決定を支援します。

例:

- 店舗推薦
- 予定確認
- 行動提案
- 情報検索
- リマインド

単純な検索結果を返すだけではなく、

- 現在の状況
- 時間
- 場所
- ユーザーの好み
- 過去の利用履歴

などを考慮した提案を目指します。

---

### 3. 情報整理

ユーザーに関する情報や活動履歴を管理し、
必要なタイミングで利用できる状態にします。

例:

- 会話履歴
- ユーザープロフィール
- 好み・価値観
- 技術経験
- 学習履歴
- プロジェクト情報
- 過去の意思決定

これらをAlice Memoryとして蓄積し、
ユーザー理解に利用します。

---

### 4. PC・デバイス操作支援

自然な指示によってPCや外部サービスを操作できる環境を目指します。

例:

- Mac操作
- アプリ操作
- YouTubeの再生・停止
- ブラウザ操作
- ファイル操作
- 外部サービス操作

将来的には音声による操作にも対応します。

---

## Core Concept

Aliceの重要な特徴は、
AIモデルそのものではなく「ユーザー専用AI」であることです。

Aliceは以下の要素によって構成されます。

- Interface
- Alice Core
- Memory
- Tools

AIモデルはAliceの推論能力を提供するコンポーネントの一つとして扱い、
Aliceそのものとは分離します。

これにより、将来的に利用するAIモデルが変更されても、
Aliceの人格、Memory、ユーザー情報、外部サービスとの連携を維持できる設計を目指します。

---

## Growth Concept

Aliceは固定された完成品ではなく、
利用によって継続的に成長するシステムを目指します。

基本的な成長サイクルは以下とします。

```text
Aliceを利用
    ↓
会話・行動・判断履歴を蓄積
    ↓
Memoryを更新
    ↓
ユーザー理解が向上
    ↓
より適切な回答・提案
    ↓
再び利用
```

---

## Development Policy

Project Aliceでは、
最初から万能なAIアシスタントを作ることを目指しません。

小さな機能から実装し、
実際に日常で利用しながら改善します。

基本方針:

- 小さく作る
- 実際に使う
- 利用結果から改善する
- 必要な能力を段階的に追加する
- 特定のAIモデルや技術へ過度に依存しない
- AliceのMemoryを長期的な資産として扱う

---

## Long-term Vision

最終的なAliceは、
ユーザーの仕事と私生活の両方を理解する
個人専用AIパートナーを目指します。

仕事では技術パートナーとして、
私生活ではパーソナルアシスタントとして機能します。

ユーザーから毎回すべてを説明されなくても、
過去の情報や現在の状況から意図を理解し、

「ユーザーにとって今何が最適なのか」

を考え、必要に応じて提案・実行できる存在を目指します。
