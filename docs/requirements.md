# Alice Requirements

## Overview

本ドキュメントでは、
Project Aliceが満たすべき主要な機能要件・非機能要件を定義します。

Aliceは段階的に能力を追加し、
最終的にユーザー専用のパーソナルAIアシスタントへ成長することを目指します。

開発フェーズの詳細については `mvp.md` を参照します。

---

# Phase 1：AI Assistant MVP

## 目的

Aliceと自然な会話ができる基本基盤を構築する。

## 機能要件

### テキストチャット

ユーザーはテキストによってAliceと会話できること。

### AI連携

Alice CoreからAI Providerを通してLLMを利用できること。

### Alice人格

Aliceとして一定の人格・行動方針を持った回答ができること。

### 会話履歴

ユーザーとAliceの会話履歴を保存できること。

保存した会話履歴を後から参照できること。

## 成功条件

- ユーザーとAliceがテキストで会話できる
- Aliceとして一貫した回答ができる
- 会話履歴を保存できる
- 保存した会話履歴を確認できる

---

# Phase 2：Personal Memory

## 目的

Aliceがユーザーについて継続的に理解できる状態を作る。

## 機能要件

### User Profile

ユーザーに関する基本情報を管理できること。

### Preference

ユーザーの好みや価値観を保存できること。

### Engineering Memory

以下のような技術情報を管理できること。

- 技術経験
- 開発方針
- 学習履歴
- 設計判断

### Project Memory

ユーザーが関わるプロジェクトについて情報を管理できること。

例:

- Project Alice
- SixTONES Schedule Bot
- その他の開発プロジェクト

### Conversation Search

過去の会話から、
現在の質問に関連する情報を取得できること。

## 成功条件

Aliceが保存されたMemoryを利用し、
一般的な回答ではなくユーザーに合わせた回答ができること。

---

# Phase 3：Tool Integration

## 目的

Aliceが外部サービスから情報を取得したり、
外部サービスに対して操作を実行できる状態を作る。

## 機能要件

### Calendar

カレンダーから予定情報を取得できること。

将来的には予定の登録・変更などの操作にも対応する。

### 店舗情報

店舗情報を取得し、
ユーザーの状況や好みを考慮した推薦ができること。

推薦時には必要に応じて以下を考慮する。

- 現在位置
- 現在時刻
- 営業状況
- ユーザーの好み
- 過去の利用履歴
- 予算

### Web

必要な情報をWebから取得できること。

### GitHub

GitHub上の開発情報を取得し、
開発支援に利用できること。

## 成功条件

ユーザーの質問に対して、
Aliceが必要な外部サービスを利用して情報を取得できること。

---

# Phase 4：Engineering Support

## 目的

Aliceをユーザー専用のエンジニアリングパートナーとして利用できる状態にする。

## 機能要件

- コードレビュー
- 設計レビュー
- 要件レビュー
- 技術選定支援
- 開発プロジェクト情報の参照
- GitHubとの連携

## 判断時に考慮する項目

- 保守性
- 拡張性
- セキュリティ
- 運用コスト
- 開発効率
- ユーザーの技術経験
- 過去の設計判断

## 成功条件

Aliceがユーザーの技術経験やプロジェクト情報を考慮し、
技術的な助言を行えること。

---

# Phase 5：Voice & Device Control

## 目的

自然な音声指示によってAliceを利用し、
PCやアプリケーションを操作できる状態を作る。

## 機能要件

### Voice Input

ユーザーの音声を認識し、
Aliceへの指示として処理できること。

### Voice Output

Aliceの回答を音声で出力できること。

### PC Control

ユーザーの指示に応じてMacなどのPCを操作できること。

### Application Control

対応するアプリケーションを操作できること。

例:

- YouTube再生
- YouTube停止
- ブラウザ操作
- ファイル操作

## 成功条件

ユーザーがキーボードやマウスを使用せず、
音声だけで基本的なAlice操作を行えること。

---

# Phase 6：Agent Capability

## 目的

Aliceがユーザーの目的を理解し、
必要な手順とToolを選択して処理できる状態を作る。

## 機能要件

### Task Planning

ユーザーの要求を複数のタスクへ分解できること。

### Tool Selection

タスクを実行するために必要なToolを選択できること。

### Tool Execution

選択したToolを適切な順序で実行できること。

### Result Evaluation

Toolの実行結果を確認し、
次の行動を判断できること。

### User Confirmation

重要な操作や取り消し困難な操作について、
必要に応じてユーザーへ確認できること。

## 成功条件

単純な一命令一操作だけではなく、
ユーザーの目的から必要な作業をAlice自身が判断して実行できること。

# Non-Functional Requirements

## AI Provider Independence

特定のLLMへ強く依存しない設計を目指す。

AI Provider Interfaceを通してAIモデルを利用し、
将来的なモデル変更に対応できる構成とする。

---

## Memory Portability

Alice MemoryはAIモデルとは分離して管理する。

AI Providerを変更した場合でも、
ユーザー情報や過去の履歴を継続して利用できることを目指す。

---

## Security

Aliceが扱うユーザー情報は個人データとして扱う。

特に以下の情報について、
不要な外部送信を避ける設計を目指す。

- 会話履歴
- ユーザープロフィール
- 行動履歴
- 認証情報
- PC内の情報

認証情報やAPIキーをAlice Memoryへ直接保存しない。

---

## Extensibility

新しいToolやAI Providerを追加する際に、
Alice Core全体へ大きな変更を必要としない構造を目指す。

---

## Maintainability

個人開発として継続的に保守できる複雑さに抑える。

将来必要になる可能性だけを理由として、
現時点で不要な機能やインフラを導入しない。

---

## Observability

Aliceが実行した処理について、
必要に応じて以下を確認できる状態を目指す。

- 何を実行したか
- どのToolを利用したか
- 実行に成功したか
- エラーが発生したか

特にAgentによる自動操作については、
後から実行内容を追跡できることを重視する。
